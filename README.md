# 吴凌多店客服工作台

一个面向拼多多绿植、雨伞店铺的客服项目。它把接待、店铺管理和人工售后分到三个端：客户端理解买家正在问哪件商品；老板看板管理店铺与服务知识；人工工作台处理需要跟进的会话和售后。

**当前发布的是三个端的源码选集，不是生产安装包，也不是可以一键自托管的完整系统。** 可以在本地运行售后判断示例，阅读两个网页端和共享知识库的实现。仓库不连接任何线上店铺。

| 端 | 代码入口 | 本次公开的内容 |
| --- | --- | --- |
| Windows 客服客户端 | [绿植](client/green/) · [雨伞](client/umbrella/) | 商品上下文、规格分类、绿植政策与售后判断；两类商品的专用代码分别保存 |
| 老板网页端 | [绿植看板](web/boss/green/index.html) · [雨伞看板](web/boss/umbrella/index.html) | 店铺经营看板、人员与配置界面、共享知识库页面 |
| 人工售后网页端 | [绿植工作台](web/staff/green/index.html) · [雨伞工作台](web/staff/umbrella/index.html) | 待人工跟进、按店铺筛选售后、订单查询和处理记录界面 |

[共享知识库模块](server/knowledge/)包含知识清洗、分类、去重、匹配和服务端存储扩展。普通问答和保修、赔付、赠品等商家承诺是两类信息；客户的一次退款结果也不是下一位客户的店铺政策。

## 先跑一个真实代码示例

需要 Python 3.10 或更高版本。在仓库根目录执行，无需模型密钥、数据库或平台账号：

~~~sh
python example.py
python -m unittest discover -s tests -v
~~~

示例用**合成订单**调用实际客户端判断函数：同样是“我要退货”，如果该单未发货且已经退款，就不该让买家再申请、寄回或拍照。它不模拟真实买家，也不会向商家后台发消息。

## 网页怎么查看

在仓库根目录启动仅本机可访问的静态服务：

~~~sh
python -m http.server 8000 --bind 127.0.0.1 --directory web
~~~

打开 [绿植老板看板](http://127.0.0.1:8000/boss/green/) 或 [绿植人工工作台](http://127.0.0.1:8000/staff/green/)；将地址中的 green 换成 umbrella 可查看雨伞版。**这里只能加载前端页面**。登录、报表、知识发布、人工接单等操作需要相应后端；打开页面不代表这些服务已连接。请勿在静态预览中填写生产账号或密钥。

## 接入时最重要的三条约定

- **商品卡不是订单。** 问“这款带盆吗”应核对商品卡和选中规格；问“我买的这盆带盆吗”应核对对应订单的规格。不能用一个买家的历史订单覆盖当前商品。
- **售后结论依赖本轮订单状态。** 将未发货、已签收、退款中、退款成功分开；查单失败不是“没有订单”。图片可以辅助核对，但不能证明某笔订单已经收货。
- **知识可以复用，客户数据不能串店。** 保留品牌、店铺、商品及规格的作用范围。赠品优先看商品与 SKU 的明确说明；有冲突时，不用通用话术替商家作承诺。

## 发布范围与限制

桌面启动程序、商家浏览器适配器、模型网关、线上身份认证与店铺授权服务、远程桌面组件及安装器**不在此次发布范围内**。部分模块引用这些宿主接口，不能脱离宿主独立运行。两个网页端来自各自的源码快照，不代表线上部署版本；仓库测试不等同于真实店铺自动发送或跨电脑同步验收。

请用虚构的商品、规格及订单状态提交问题。不要上传店铺数据库、买家对话或照片、Cookie、网关密钥、设备注册信息、线上配置或含客户资料的截图。
