# 拼多多 AI 智能客服

面向多店铺的 AI 接待、商品学习与人工售后工作台。买家发来商品卡，客服按**这件商品、这个规格**回答；买家问退款，则先核对**这位买家的这笔订单**。接待结束后，系统还能从人工和 AI 的有效回复里积累知识，让下一家店少学一次，让下一次回答更贴合商品。

项目把**通用客服流程**和**品类知识**分开：消息接待、订单判断、知识审核和多端协作可以复用；商品属性、赠品和售后承诺不能互相照搬。本仓库用绿植和雨伞展示两种接入方式，不是只服务这两个品类，也不是装上后就懂所有商品。

> **这个仓库能直接用来做什么？** 运行客户端判断示例和测试，查看两套品类的老板看板与人工工作台前端，阅读商品上下文、售后规则及知识库存储与同步代码。下文也介绍完整客户端的工作方式；**桌面主程序、拼多多商家浏览器适配器、完整自动学习任务、WB 网关和生产后端未随本仓库发布**。克隆仓库不会自动登录店铺或给买家发消息。本项目不是拼多多或 WorkBuddy 的官方产品。

## 三个端，分别给谁用？

| 端 | 使用者 | 主要工作 |
| --- | --- | --- |
| Windows 客服客户端 | 接待人员、店铺运营 | 接入本机模型通道；从商家后台学习商品；识别买家连发的文字与卡片；结合当前 SKU、订单和已发布知识生成回复。完整客户端负责实际发送。 |
| 老板看板（网页） | 店主、运营负责人 | 查看店铺经营指标、接入电脑及人员；查看、编辑、发布或撤回共享知识；统一管理适用店铺的承诺与备用 AI 通道。 |
| 人工售后工作台（网页） | 负责对应店铺的售后人员 | 集中查看待人工跟进与已同步售后，按负责店铺、状态、订单或商品搜索。客服能处理的问题留在会话里，需要人决定的事项才交到这里。 |

源码入口：**[客户端](client/)** · **[老板看板](web/boss/)** · **[人工售后工作台](web/staff/)** · **[共享知识服务](server/knowledge/)**

## 1. 从商品后台自动学习，而不是靠客服手填问答

- **先认商品，再认规格。** 商品标题、类目和公共属性属于商品；颜色、尺寸、数量、套装内容等可能属于某个 SKU。买家换了一张商品卡，不能继续拿上一款的参数回答。
- **详情图用来补信息。** 除了图上的字，款式、结构、外观差异也可以成为线索。装饰道具不等于赠品，画出来的尺寸比例也不是实测值。只有能和当前商品、规格核对的内容才适合作为事实。
- **把参数翻译成买家能用的答案。** 买家问“两个人用会不会挤”，不是要听一串规格名。有可核对的展开尺寸，就围绕遮挡范围给选购建议；比较两款时只说两款确实不同的地方，不凭空认定更耐用。
- **选购图跟着商品走。** 完整客户端可把当前商品与选中款式的已知参数整理成图，方便买家看。规格没选定时，不应把某个颜色或套装写成全款标配。
- **避免重复学习。** 已有商品资料可以复用；优先补缺失项、处理变化项。这样不必每家店、每轮会话都把整份历史和全部图片再交给模型。

## 2. 为什么会“越用越聪明”？

这里的学习是**积累、纠正和检索知识**，不是拿买家对话训练模型权重，也不是把 AI 说过的话自动当成真的。完整客户端把学习放在后台，不让正在等回复的买家排在审核任务后面。

| 环节 | 系统做什么 |
| --- | --- |
| 收集候选 | 从已发送的人工回复、AI 回复以及导入的历史问答里提取候选。输入框里的草稿不是已验证经验。 |
| 提炼与纠错 | 将原对话改写成可复用的“典型问题 + 有条件的回答”，结合当前商品和已有知识核对；不把某位买家的订单、退款结果或联系方式写成通用答案。 |
| 去重与复核 | 先识别重复记录，再检查同义表达与适用条件。“随单带盆”和“这款含一个花盆”可能是同一知识；“裸苗款不带盆”则不是重复项。 |
| 决定是否入库 | 有依据、适用范围明确且通过复核的知识自动入库；新保修期限、赔付、补发、赠品等承诺，以及会影响回答的冲突，交老板确认。无价值或明显错误的回复不拿来教下一轮。 |
| 发布、下发与撤回 | 已发布知识带版本同步到适用客户端。新电脑、新店铺可以复用同一范围的知识；老板更正或撤回后，客户端在同步时更新，不该继续把旧版本当依据。 |
| 在下次接待中使用 | 检索的是本轮相关的事实和处理方法，不是原话复制。共享经验不能覆盖当前 SKU、实时订单或商品例外规则。 |

**举个例子：** 人工答过“红色带盆款是原盆发货”，这条经验可以帮助客服回答其他买家对**同一带盆规格**的咨询。它不能被学成“全店都送盆”，更不能因为 AI 重复说了几次就升级成店铺承诺。公开的[知识清洗与匹配规则](server/knowledge/knowledge_core.py)和[版本同步存储](server/knowledge/server_extension.py)可以单独阅读；完整后台审核循环不在这次源码选集中。

## 3. 实时接待：记住该记的，不反复提旧问题

| 买家怎么问 | 客服应该依据什么回答 |
| --- | --- |
| 发商品卡后问“这款带盆吗？” | 查这张卡及选中规格。SKU 明确写“含盆”或“不含盆”就按 SKU 答；商品没有说明时，再核对适用的已发布政策。 |
| 先发“几骨的”，紧接着发“我要退款” | 短暂等待同一会话的连发消息，保留两个意图。骨数查商品，退款查当笔订单；一次说清，不能只回第一问。 |
| 发两款商品后追问“那哪款大？” | 沿用刚对比的两款，看同一口径的尺寸；只有确实分不清买家指哪款时才请对方选择。 |
| 下单前问“万一收到花蔫了怎么办？” | 按售前保障咨询回答，用店铺已经发布的承诺说明处理方式，不把假设说成已收货事故，也不直接让买家传照片。 |
| 问“我要退货”，订单显示“未发货，退款成功” | 告知这单已退款、无需寄回或重复申请。查单超时不等于没有订单，历史退款也不代表本轮订单已退款。 |
| 刚问完售后，又问“这款是什么材质？” | 切回商品咨询，回答当下的问题，不再夹带之前的退款、损坏或订单历史。 |

## 4. 模型接入：WB 本机反向代理 + 统一备用通道

**WB 指 WorkBuddy。** 在完整 Windows 部署里，客服客户端不必自己适配每个模型的调用方式。本机运行的 WorkBuddy 网关（workbuddy2api）把当前电脑已登录账号的模型能力，适配成客户端可调用的聊天接口：

~~~text
本机客服客户端 → 本机 WB 网关（回环地址）→ 当前电脑的 WorkBuddy 账号
                    主线路不可用时 → 按配置使用备用模型通道
~~~

| 配置项 | 怎么理解 |
| --- | --- |
| 主通道按电脑配置 | 每台电脑沿用自己的 WorkBuddy 登录与网关密钥。老板后台统一设置的是备用线路，不应拿一台电脑的本地地址和密钥覆盖其他电脑。 |
| 接口地址与密钥分开 | 地址形如 `http://127.0.0.1:{本机端口}/v1/chat/completions`，端口以本机配置为准；它是请求地址，**不是 API Key**。 |
| 就绪要验证凭据 | 端口能连不代表模型能用。完整客户端区分“网关在运行”和“密钥已匹配”，验证成功再使用；换安装目录时先尝试复用本机已有绑定。 |
| 备用线路单独维护 | 管理端可配置备用接口地址、模型名和对应凭据。切换的是模型通道，不是买家、店铺或订单上下文。 |

**首次接入顺序：** 先登录本机 WorkBuddy → 检查或启动网关 → 测试模型连接 → 再开启商品学习与自动接待。回环接口留在本机；不要把网关密钥放进 Issue、网页源码或店铺知识库。**仓库未附带 WorkBuddy、本机反代程序或可共用的账号密钥。** 运行下面的示例不需要 WB。

## 5. 如何扩展到其他品类

1. **定义品类字段。** 用“商品公共属性 + SKU 专属属性”组织资料。例如收纳用品可以定义尺寸、容量、材质和件数，而不沿用绿植的盆型或雨伞的骨数。
2. **接上本品类的事实和政策。** 商品卡、订单商品、店铺通用保障分别保存；明确哪些字段能用于比较，哪些承诺必须由老板发布。
3. **用真实问题的合成样例验收。** 至少覆盖切换 SKU、两款比较、连发两问、退款状态变化、知识撤回。测试数据不要包含真实买家或订单。
4. **再连接生产宿主。** 商家浏览器适配、账号授权、消息发送、同步服务和模型网关需要另外接入。新增一个品类名称不等于已完成上线验证。

## 本地快速体验

需要 Python 3.10 或更高版本。在仓库根目录运行，无需账号、数据库和模型密钥：

~~~sh
python example.py
python -m unittest discover -s tests -v
~~~

示例用合成订单调用实际判断函数。还可以启动只监听本机的静态预览：

~~~sh
python -m http.server 8000 --bind 127.0.0.1 --directory web
~~~

| 本机预览 | 绿植示例 | 雨伞示例 |
| --- | --- | --- |
| 老板看板 | [打开看板](http://127.0.0.1:8000/boss/green/) | [打开看板](http://127.0.0.1:8000/boss/umbrella/) |
| 人工售后 | [打开工作台](http://127.0.0.1:8000/staff/green/) | [打开工作台](http://127.0.0.1:8000/staff/umbrella/) |

静态预览展示前端，不提供登录、报表数据、远程桌面、自动发消息或线上知识下发。请不要在预览中填写生产凭据。提交 Issue 时，欢迎附上**脱敏问题、当前商品规格、合成订单状态和预期回复**，不要附原始对话库、Cookie 或客户照片。
